1 / Start here

1. Start here

CommonsLens is easiest to understand as a research desk around Wikimedia Commons: it helps you find public media, make sense of the available context, organize references, and move useful results into a real project.

Purpose

This section gives you the mental model and the shortest complete workflow. By the end, you should be able to find one file, inspect what it says about itself, check the reported reuse information, create an attribution draft, and decide whether to bookmark, download, or continue searching.

What is CommonsLens?

CommonsLens is an independent, non-commercial interface for exploring Wikimedia Commons. It adds a more task-oriented layer over the public archive: visual search, guided filters, map discovery, file inspection, reuse helpers, local bookmarks, CSV exports, and repeatable pipelines.

Discover

Search by words, media type, format, category, Wikidata subject, quality, license, date, technical properties, or location.

Understand

Bring the creator, uploader, descriptions, dates, dimensions, categories, assessments, coordinates, structured data, usage, and source links into one viewer.

Organize

Keep file references in browser-local bookmarks and folders, or preserve a larger workflow as a pipeline.

Move results onward

Copy attribution drafts, download media, share a search URL, or export metadata and media URLs for another tool.

CommonsLens versus Wikimedia Commons

CommonsLens does not replace Wikimedia Commons. Commons is the archive, the original file page, the contributor history, and the authoritative place to read the complete rights information. CommonsLens is a convenience layer for finding and working with that public material.

QuestionCommonsLensWikimedia Commons
What is it best at?Fast discovery, visual filtering, geographic exploration, organization, and repeatable research workflows.Archival context, file history, community discussion, source information, and the complete file page.
Does it host or own the media?No. It requests and displays public media and metadata from Wikimedia services.It is the Wikimedia-hosted source for the file and its page history.
Where should I verify a license?Use its rights panel and generated attribution as a starting point.Read the original file page and its full license, templates, notices, and history.
Where is my personal workspace?In this browser: bookmarks, folders, preferences, and pipelines are local.Commons has its own account and community systems, which are separate from CommonsLens.

What you can do

  • Find a single image, diagram, audio file, video, document, or 3D file.
  • Build a candidate collection using categories, subjects, licenses, quality assessments, dates, dimensions, file size, or location.
  • Inspect a file without losing the search result context that led you there.
  • Prepare an attribution draft in plain text, HTML, or WikiText.
  • Save references locally, export metadata, or construct a repeatable pipeline for a larger task.

What CommonsLens does not do

  • It does not make an unlicensed file legal to reuse.
  • It does not guarantee that a Commons record is complete, accurate, current, or suitable for your particular publication.
  • It does not create a private cloud library or sync your bookmarks and pipelines between devices.
  • It does not silently download every result when you search or export a CSV.
  • It is not a bulk crawler, scraping endpoint, legal service, or replacement for checking the original file page.

No account required

You can search, inspect, map, download, export, and use the reuse helpers without creating a CommonsLens account. The trade-off is that browser-local work is tied to the current browser profile and site origin. Opening the app on another device will not bring your bookmarks or pipelines with it unless you export and move them yourself.

Before you begin

  1. Decide whether you are looking for one known file, a collection, a location-based set, or a repeatable dataset. That choice determines the shortest route through the app.
  2. Have a few search terms ready, but do not worry if they are not the exact Commons vocabulary. Browse and advanced filters are there to help you discover that vocabulary.
  3. If you plan to publish anything, reserve time to verify each selected file at its original Commons page. Treat CommonsLens’ reuse panel as an assistant, not the final authority.
  4. Do not enter confidential information into searches, pipeline names, notes, or URLs. Search state can be copied into browser history or shared with someone else.

What you see when you open CommonsLens

The homepage is the Search workspace. Its controls appear in layers so you can start simply and become more precise only when needed:

  1. Search field: enter a phrase or use autocomplete for a direct file-title match.
  2. Media scope: choose All, Images, SVG / Diagrams, Audio, Video, Docs, or 3D.
  3. Format chips: once a scope is selected, choose a concrete format such as PNG, SVG, PDF, MP4, or STL.
  4. Filters: open the filter panel to narrow by classification, quality, license, dates, metadata, or location. On a phone this is a Filters button; on a wide screen it can remain docked.
  5. Results: cards load progressively. The count may show a + when more results are available.
  6. View and sort: switch between Grid and Map, then sort by relevance, title, edit date, or creation date when results are present.
  7. Query preview: expand it after a search when you want to see the Wikimedia-oriented query that CommonsLens constructed from your choices.

Five-minute first search

Use this tutorial once before exploring the deeper sections. The example uses Apollo 11, but any subject works.

  1. Open Search. Start from the CommonsLens homepage. You do not need to sign in.
  2. Enter a useful phrase. Type Apollo 11 and press Enter for a result set. If autocomplete offers a direct file-title match, selecting it is a shortcut to that file; pressing Enter keeps the broader search.
  3. Choose the scope that matches the task. Use Images for photographs, SVG / Diagrams for vector work, Audio or Video for moving media, Docs for PDF/DjVu, 3D for STL, or All when the kind of file is part of what you are discovering.
  4. Narrow only if necessary. Pick a format chip, open filters, or sort the result set. Every active filter appears as a removable chip so you can see what is changing the query.
  5. Open a result card. The viewer shows the selected file while preserving the surrounding result queue. Read the title, creator, uploader, description, dates, file details, categories, assessments, and coordinates when they exist.
  6. Open the reuse area. Check the reported license, creator, preferred credit, usage terms, restrictions, and attribution status. Choose Attribution, HTML, or WikiText and copy the generated draft if it is useful.
  7. Verify before publishing. Select View Source Page and read the original Commons file page, full license, notices, and any file-specific restrictions. Resolve missing or conflicting metadata there.
  8. Choose what happens next. Bookmark the reference for later, download the original or a displayed derivative, copy the file URL, or export it with other selected results.
The most important habit: discovery and legal verification are separate steps. A result that appears in a license-filtered search is a useful candidate; it is not a promise that the file satisfies your project’s legal, privacy, publicity, trademark, or cultural requirements.

What a good first result looks like

You should be able to answer four questions before you use a file:

  1. What is it? You understand the title, description, media type, dimensions, and relevant context.
  2. Who made or uploaded it? You can distinguish the creator from the uploader and know where to inspect the uploader’s portfolio.
  3. What may I do with it? You have read the reported license and restrictions, generated a draft credit if appropriate, and checked the source page.
  4. How can I find it again? You have a source URL, bookmark, export row, or saved pipeline rather than relying on memory.

2 / How your data moves

2. How your data moves

CommonsLens is deliberately a browser-first application. There is no CommonsLens account, analytics profile, or private application database receiving your research. Your browser contacts the providers needed for the feature you use, while selected workspace data stays in browser storage.

Purpose

This section lets you predict where information goes before you click. The most important distinction is between public-service requests and local workspace state: a search must contact Wikimedia to return results, while a bookmark is just a file reference saved in this browser.

Before you begin

  • Assume that search terms, file names, usernames, coordinates, and filter choices are sent to the provider needed to answer the request.
  • Assume that anything in a shareable URL can be seen by anyone who receives the link, and may also appear in your browser history or bookmarks.
  • Do not put passwords, private research notes, personal identifiers, or confidential project names into searches, pipeline names, pipeline notes, or URLs.
  • If you use private browsing or a restrictive storage policy, local saves may fail or last only for the current session. The application is designed to keep working where possible, but local persistence is best effort.

What you see

The app does not expose a privacy dashboard or a hidden “sync” state. You can infer the important boundaries from the visible action:

Search and filtersResults, autocomplete, categories, templates, subjects, and metadata appear after browser requests to Wikimedia services.
Bookmarks and foldersThe bookmark action changes this browser’s local collection. It does not create a CommonsLens account or upload a private collection.
PipelinesGraph edits autosave locally. Running a graph creates provider requests and may create local result/metadata cache entries.
Downloads and exportsThe browser starts a download to the location chosen by your browser. CommonsLens does not receive a copy of that saved file.
Map layersMedia search still uses Wikimedia; visible map tiles are requested from OpenStreetMap or Esri depending on the selected layer.
Copy attributionOnly the text you explicitly copy is written to the browser clipboard. CommonsLens does not read or upload the rest of your clipboard.

What is sent to external services

  • Wikimedia Commons and Wikidata: search terms, filters, file titles, usernames, category/template/subject lookups, coordinates, metadata requests, thumbnails, previews, and media requests needed for the feature you use.
  • OpenStreetMap: visible multilingual street-map tiles when that map layer is selected.
  • Esri: visible English street-map, satellite, hybrid, and reference tiles when those layers are selected.
  • GitHub Pages: hosts the application and static documentation, so the hosting provider can receive ordinary requests for those files.
  • Linked external sites: opening a source page, license, global-usage page, repository, or provider policy takes you to that site under its own privacy and logging rules.

As with ordinary web use, providers may receive standard request information such as IP address, user agent, requested resource, time, and referrer where supplied. CommonsLens does not add an analytics layer, advertising profile, session recorder, or behavioural tracking service on top of those provider requests.

Important limitations

Local does not mean indestructible. Browser storage can be cleared, denied, evicted, corrupted, or isolated by private browsing and browser profiles. Export important bookmarks or pipelines if you cannot afford to lose them.
  • There is no account recovery for browser-local bookmarks or pipelines. A JSON pipeline export is the portable backup; bookmarks currently need to be preserved through their URLs or a metadata export.
  • Clearing all site data can remove bookmarks, folders, preferences, saved graphs, cached results, and other browser-managed state at once.
  • Pipeline Clear Cache is narrower: it removes cached results and metadata, not saved graphs.
  • Provider requests are not anonymous simply because CommonsLens has no account. Provider policies and ordinary web logs still apply.
  • URLs and CSV files can contain public file links, search terms, usernames, coordinates, and filters. Treat them as shareable research artifacts, not secret containers.

3 / Search

3. Search Wikimedia Commons

Search is the main way to move from an idea to a usable Wikimedia Commons file. Start with ordinary words, then narrow the result set only when the results show you what needs correcting.

Purpose

This section teaches the complete search loop: describe what you need, choose the right media scope, inspect the results, refine the query, and preserve the search recipe if you want to return to it later.

Before you begin

  • Decide whether you are looking for a subject, a particular file, a file type, or media near a place.
  • Use the words a contributor might have used in a title, caption, category, or description. Commons is not a general web search engine.
  • If the result must meet a technical or rights requirement, keep that requirement in mind while searching; it can be added with Advanced filters.

What you see

Search landing page

The starting screen offers the search field and example searches. Examples are shortcuts into real workflows, not a separate sample dataset.

Autocomplete suggestions

Suggestions are direct file-title matches from Wikimedia. Selecting one opens that file search immediately; pressing Enter searches the full phrase.

Search workspace

After a search, the workspace exposes media scopes, format chips, filter controls, sort order, result count, Grid/Map view, and the query preview.

Result cards

Each card gives you a preview, title, media type, and quick actions. Select a card to inspect it, bookmark it, add it to the persistent download queue, or download it individually.

Progressive loading

Results arrive in pages as you scroll. The number shown is the number currently loaded, and a trailing + means another page may be available.

Step-by-step: run a useful search

  1. Describe the thing. Type a phrase such as red fox, Apollo 11, or DNA helix. Start broad enough to learn the vocabulary in the results.
  2. Submit the search. Press Enter or use the search action. CommonsLens sends the search request to Wikimedia and opens the results workspace.
  3. Read the first results. Look at titles, previews, media-type badges, and repeated words. Those repeated words often reveal the category, institution, language, or spelling used by Commons.
  4. Choose a media scope. Use All for discovery, or select Images, SVG / Diagrams, Audio, Video, Docs, or 3D when the media type is part of the requirement.
  5. Narrow to file formats when needed. Select one or more formats such as PNG, SVG, PDF, MP4, or STL. Multiple selected formats mean “match any of these formats.”
  6. Refine the meaning. Add filters when words are ambiguous or when the output must meet a date, dimensions, license, quality, category, location, or metadata requirement. See Advanced filters.
  7. Change the order. Use Relevance for discovery; use Title A–Z for predictable scanning; use edited or created date when recency or historical order matters.
  8. Inspect before acting. Open a result to check its public metadata, source page, reuse information, and original-file link. See Inspect a file.
  9. Keep or share the recipe. The URL records the search choices so another person, or your future self, can reopen the same query setup. It does not freeze the current result set.

Use autocomplete correctly

Autocomplete is for finding a direct file-title match quickly. A suggestion is not a private copy and it does not bypass Wikimedia: selecting it still opens a CommonsLens search for that file title. If you want all matching files, ignore the suggestion and press Enter instead.

Use text query syntax

The Search field and the pipeline’s Text Query source accept Wikimedia’s CirrusSearch syntax. CommonsLens forwards the query text to Wikimedia, with one CommonsLens-specific exception: spaced + creates separate result branches. The table below covers the most useful actions.

Remember that quotes mean an exact phrase, not a general “make this term mandatory” switch; for separate OR-style concepts in CommonsLens, use the spaced + behavior documented above.

Search using filters without a text phrase

You can begin with a media scope, format, or meaningful filter instead of a text query. For example, choose Images and PNG to discover PNG images, or combine a location and date filter for a map-oriented task. If you apply filters and the results look unexpectedly broad, check the active chips and the query preview before adding more conditions.

Read the query preview

The query preview is a transparency aid. It shows the search recipe CommonsLens is building from your text and controls, which helps explain why a filter is present and makes a shared URL easier to discuss. It is not a promise that every visible clause becomes one literal provider request: some multi-value filters are sent as separate requests and merged so the intended result set is preserved.

What happens to your data

  • Your query text, selected filters, sort order, language choice, and location values are used in the browser to build the search request.
  • The request goes directly from the browser to Wikimedia services and, when the map is used, to the selected map providers. CommonsLens displays and combines the responses.
  • Loaded result metadata and thumbnails are held in the current browser session. They are not automatically added to your bookmarks or uploaded to a CommonsLens account.
  • When you copy or share the URL, it can contain search terms, filters, usernames, and coordinates. Anyone with that URL can read those values.

What is saved locally

The search URL is the portable record of the query setup. Search results themselves are not a permanent snapshot: Wikimedia metadata can change, new files can appear, and result ordering can change when you reopen the URL. Bookmarks, folders, and other local preferences are separate from the current search session; see Sharing and local state.

Important limitations

  • Search quality depends on Wikimedia’s titles, descriptions, categories, structured data, and indexing. A missing or differently worded description can make a relevant file hard to find.
  • Text search is not the same as visual similarity. Searching for red fox does not guarantee that every returned preview visibly contains a red fox.
  • Filters can be broader or narrower than ordinary language suggests. Read the active chips and preview, then confirm the file’s metadata in the viewer.
  • A loaded count is not the total number of matching files. The + marker means more results may be available.
  • A search result is a lead, not proof of reuse permission. Verify the source page, license, creator, and required attribution before publishing anything.

4 / Advanced filters

4. Use advanced filters

Advanced filters turn a broad search into a deliberate research question. They are useful when words alone are too ambiguous, when you need a particular kind of metadata, or when the result must meet a technical or reuse-related requirement.

Purpose

Use this panel after an initial search has shown you what Commons calls the thing you are looking for. A good filter makes the result set more useful and explainable; a stack of filters added without checking the result set can quietly remove the files you needed.

Before you begin

  • Run a broad search first when you do not know the Commons vocabulary. Read titles, categories, and structured metadata before choosing a narrow term.
  • Know whether your requirement is about subject, classification, rights, quality, dates, technical properties, or location.
  • Keep the result count and active chips visible while refining. If the count drops unexpectedly, remove the last filter or switch its combination mode before adding another.

What you see

On a wide screen, the filter panel is docked beside Search. On a smaller screen, open it from the Filters control as a drawer. The panel has a group rail and a group-specific editor:

Panel layout and autocomplete behavior

  • Classification is the starting group. When the filter panel opens, Classification is selected by default so the primary group list has a predictable starting point.
  • The secondary editor starts minimized. The group-specific editor stays closed until you select a group or use its expand control. This keeps the group list available on both desktop and mobile instead of opening a large panel over the workspace.
  • Desktop and mobile use the same controls. On a wide screen the panel is docked; on a phone it opens as a drawer. The primary group list remains available, and selecting a group opens its secondary editor.
  • Suggestions are optional. Subject, property, category, and template fields can show matching suggestions while you type. Select a suggestion when you need the exact Wikidata Q-code, property/value pair, category, or template name. If suggestions are unavailable, the field displays a connection error and you can still submit the complete search term.
  • Mobile suggestions stay above the keyboard. If the keyboard covers the lower part of the drawer, the suggestion list is positioned in the available visible space. Dismiss the keyboard or scroll the drawer if the viewport is especially short.

Sidebar navigation and diagnostics

The primary sidebar separates the main filter groups from the additional navigation links with a divider. The links for All features and User guide are below that divider. A small request-log icon sits at the bottom of the primary sidebar; on the landing page, the same icon is in the top-right corner. These icons open the in-app Wikimedia request log without changing the current search.

Step-by-step: refine a search

  1. Open Filters. On desktop, use the docked panel. On a smaller screen, open the Filters drawer from Search.
  2. Choose one group. Start with the filter that expresses the most important requirement. For example, choose Classification for “files depicting a cat” or License for “CC BY-SA files.”
  3. Choose or type a value. Use autocomplete when the value represents a Commons category, template, Wikidata subject, property, or structured entity. Suggestions reduce spelling and identity mistakes.
  4. Choose include or exclude. The + mode adds a requirement; the − mode removes matching files. Existing values appear as chips and can be deleted individually.
  5. Choose how several included values combine. Intersection means every included value must match. Union means any included value may match. Excluded values are removed either way.
  6. Apply ranges deliberately. Date and numeric fields keep typed values locally until their group’s Apply button is used. An unfinished or empty field is not treated as an active range.
  7. Read the main Search view. Check the result count, active chips, and query preview after each meaningful change. A filter is only useful if the result set still answers the question.
  8. Remove or adjust. Delete an active chip to clear that value, switch Intersection to Union when the set is too narrow, or remove an exclusion when expected files disappear.

Classification

This group is the most precise way to describe what a file is about when free-text search is too ambiguous.

  • Depicts (subject): search Wikidata entities such as a person, place, object, or species. Pick a suggestion so the filter carries the subject’s Q-code, not just a spelling of its label.
  • Wikidata property search: choose a property first, then choose its value. For example, a property such as “location of creation” can be paired with a place. The completed property/value pair becomes one filter rule.
  • Categories: search Commons categories. Strict mode looks in the selected categories; Include nested subcategories switches to Commons’ server-side deep-category search. The browser does not walk the category tree itself, but very broad roots can still be slow or incomplete.
  • Read the category chip: Category: name means direct/strict mode. Category + subcategories: name means nested/deep mode. If the latter appears unexpectedly, turn off Include nested subcategories before retrying.
  • Templates: search labels attached to file pages, including institutional, collection, source, and rights-related templates. A template is metadata attached to a page; it is not the same thing as a category.

For Depicts, Wikidata properties, and categories, use Intersection when one file must satisfy every included value. Use Union when any one included value is enough. This choice applies only to the included values in that group; exclusions remain exclusions.

Quality

The Quality group searches for Commons assessments, not a computer vision score and not a guarantee that an image is suitable for your particular publication.

  • All media: remove the quality restriction, including files without one of the listed assessments.
  • Quality Media, Valued Media, Featured Media: select one or more named assessments. Multiple selected assessments match any selected assessment.
  • Individual: match the selected assessments exactly.
  • This tier + above: expand one selected assessment using CommonsLens’s displayed tier order. This is a convenience grouping of separate Commons assessments, not an official numeric quality scale.

License and attribution

License presets are useful for discovery, especially when you are building a shortlist. Select multiple presets when any of them is acceptable. A single file may expose more than one license, so open the asset viewer and source page before deciding how to use it.

The attribution control has three states: Any attribution, Attribution required, and No attribution required. This is based on reported metadata and is a search aid. It is not legal advice and cannot account for every privacy, personality, trademark, moral-rights, or jurisdiction-specific issue.

Dates

All date fields use YYYY-MM-DD and have From and Before inputs:

Date fieldWhat it meansImportant detail
Submitted to Wikimedia CommonsWhen the Commons file page was created.This is an upload/submission proxy, not necessarily when the depicted work was created.
Last image-page editWhen the Commons page was last edited.Editing metadata can change this without changing the media itself.

From is the lower boundary and Before is the upper boundary. A date range can be open-ended: enter only From for “on or after” or only Before for “earlier than.”

Metadata and technical properties

  • Language: enter a language code such as en. Submit it or leave the field to apply it.
  • Content model: enter a Commons content model such as wikitext. This describes the page’s content model, not the media’s file format.
  • Resolution bounds: set minimum or maximum width and height in pixels. Use this when the output must meet a display, print, or processing size.
  • File size: enter minimum or maximum size in MB or KB. CommonsLens converts the chosen unit to bytes for the search.
  • Color depth: choose a bit depth such as 1-bit, 8-bit, 16-bit, 24-bit, or 32-bit when that technical distinction matters.

Numeric fields are intentionally applied as a group. This lets you finish typing a lower and upper bound without sending a new search after every keystroke. Clearing a field and applying the group removes that bound.

How filters combine

Different filter groups normally combine as AND: a result must satisfy the text query, media scope, category/subject rules, date rules, and technical requirements that are all active. Inside some groups, the control you choose changes the relationship among included values:

Example: “Depicts a cat or a dog, is in the Animals category, is not in the Illustrations category, and is at least 2000 pixels wide” uses Union for the two subjects, an included category, an excluded category, and a metadata lower bound. Those separate requirements still work together.

What happens to your data

  • Autocomplete text and selected category, template, subject, and property values are requested from Wikimedia or Wikidata services as you use the pickers.
  • Applying filters rebuilds the search request in your browser and sends the active query and filter values to Wikimedia services. The map group can also open map-provider requests.
  • Results, active filter state, and typed-but-not-yet-applied range values live in the current browser session. Applying a filter changes the current search; it does not create a bookmark or upload a dataset.
  • The URL can preserve the active filter recipe. It may therefore reveal search terms, selected categories or subjects, dates, license choices, and coordinates when shared.
  • Some controls are applied after Wikimedia returns data. In particular, attribution requirement and original-media dates depend on metadata returned for each result. An ordinary search may inspect more result pages to fill the requested set; a pipeline preview intentionally checks one result page to stay responsive, while a full export continues through additional pages.

Important limitations

  • Structured metadata is incomplete and uneven. A file can be relevant but absent because its page lacks the category, subject statement, template, license statement, or date you filtered for.
  • Categories and templates are contributor-maintained labels, not a universal taxonomy. A category name can be exact, deep, broad, or unexpectedly curated.
  • “Attribution required” and license presets describe reported Commons metadata. They do not clear every right or replace reading the full source-page license.
  • Original-date filtering is only as complete as the media metadata. Missing, ambiguous, or unparseable dates cannot match an active original-date range.
  • Very restrictive combinations can produce zero results even when each filter separately returns files. Remove filters one at a time to find the narrowing condition.
  • The query preview explains the intended recipe. Some multi-value filters are executed as separate provider requests and merged, so the preview is not always one literal request string.

5. Browse categories, templates, and subjects

Browse is the vocabulary-finding tool. Use it when you know the general idea but do not yet know the exact Commons category, template, or Wikidata subject that will produce a useful search.

Purpose

The Browse page exposes three different public directories in one place. You can inspect the names people use on Wikimedia Commons, see a little context, and send a selected entry into Search as an inclusion filter.

Before you begin

  • Open Browse from the Search filter panel or from the app’s Browse navigation.
  • Start with the directory that matches the kind of knowledge you have: a filing label, a page template, or a real-world subject.
  • If you already know the exact value and need to exclude it, use Advanced filters instead. Browse adds values; it does not provide the exclusion controls.

What you see

TabWhat it containsWhat selecting an entry does
CategoriesCommons category names and a displayed file/page count for each category.Selects categories in Browse; press Apply to send the selected set to Search.
TemplatesMediaWiki template names used on Commons file pages.Adds the template as an included template filter and returns to Search.
Depicts (Q-Codes)Wikidata items returned for a subject search, with a label, Q-code, and description when available.Adds the selected Wikidata subject as an included Depicts filter and returns to Search.

Step-by-step: find and apply a classification

  1. Open the right tab. Choose Categories for filing structure, Templates for page labels, or Depicts for a structured real-world subject.
  2. Search the directory. Enter a category/template name prefix, or a subject phrase in Depicts, and submit it. Categories and templates reload with entries beginning with that value; Browse does not search the contents of every file description.
  3. Read the returned context. Category rows show a displayed count; template rows identify the item as a MediaWiki Template; Depicts rows show the Q-code and an entity description.
  4. Select the best entries. Click the main part of a category row to toggle it. Selected categories remain visible as removable chips while you continue browsing; click the wide Open area to enter a branch.
  5. Apply the selection. Press Apply once you have chosen the categories you want. Browse then sends the selected set to Search as included category filters.
  6. Continue refining in Search. Search can combine the new classification with text, media type, format, license, quality, dates, technical limits, and location.
  7. Inspect the result evidence. Open a file and check its source page and structured metadata. A classification is a contributor-maintained signal, not proof that every returned file is a perfect match.

Categories

Categories are the filing structure used to group pages on Commons. A category may be broad, institutional, geographic, historical, technical, or curated for a particular collection.

  • The directory is a vocabulary browser, not an image gallery. Category rows show names and counts; thumbnails appear after you select a category and Search loads matching files.
  • Use the category search field to jump to a name prefix, such as Architecture.
  • Each row shows a displayed size from Wikimedia’s category directory. Treat it as orientation, not as the final number of files your Search query will return.
  • Selecting a category adds it as an included category filter and starts in direct/strict mode. In Search, enable Include nested subcategories only when descendants should count.
  • Direct mode uses Commons’ incategory search for files assigned directly to the selected category. Nested mode uses one server-side deepcat search; it does not expand every child category in the browser.
  • Applying several broad categories with nested mode can still exceed Commons’ deep-category limit. The result may show a warning such as “too many categories” or “deep category search timed out” and contain no images. That means the category search was incomplete; it is not a thumbnail-loading failure. Turn off nested mode, narrow the categories, or try them separately.
  • Use Advanced filters if you need category Union/Intersection behavior, exclusions, or several categories at once.

Templates

Templates are reusable labels placed on page source by Wikimedia contributors and tools. They can identify an institution, collection, source, rights statement, maintenance state, or other page-level fact.

  • Search a real template prefix such as PD-USGov or Institution. Browse lists actual namespace-10 pages, not arbitrary values that happen to appear inside template source.
  • Browse displays the template name without the Template: namespace prefix.
  • Selecting a template adds it as an included template filter. It does not by itself prove that a file carries a particular license.
  • For license discovery, use the License group and then verify the actual license on each source page.

Depicts and Q-codes

Depicts uses Wikidata entities to describe what a file depicts. A Q-code identifies one entity even when its label could be spelled or translated in several ways.

  • Search for a subject such as City, Eiffel Tower, or a person’s name.
  • Compare the label, Q-code, and description before selecting an item. Similar labels can refer to different people, places, species, or concepts.
  • Selecting an item adds the entity to the included Depicts set. It does not automatically add a text phrase with the same label.
  • Use the Search filter panel when you need to exclude a subject or choose Intersection versus Union for several subjects.

What happens to your data

  • Category and template prefixes are sent from the browser to Wikimedia Commons’s public directory API. The directory response is displayed in the page.
  • Depicts searches are sent to the Wikidata-backed autocomplete service used by CommonsLens. The returned entity label, Q-code, and description help you choose a value.
  • Selecting a category does not download the directory or create a local collection. It stays in Browse until you press Apply; Apply updates the current Search state and navigates to a Search URL containing the selected filters. Template and Depicts selections still apply immediately.
  • If you arrived from an existing search, the selected category, template, or subject is added to that search’s current state. The existing query and compatible filters remain in place.
  • The resulting URL can be copied or shared. It may reveal the selected category, template, subject Q-code, query text, or other filters preserved from the previous search.

Request and loading behavior

  • Opening a category branch requests its immediate subcategories. Searching category names uses Wikimedia’s category directory; both are paginated and request another page only when needed.
  • Searching templates uses actual namespace-10 template pages and groups colon-separated names in the interface. A value such as Institution:Metropolitan Museum of Art is usually text inside the real Institution template, not a separate template page.
  • A normal single-category search is one Commons search request, followed by image metadata or thumbnail continuation requests when Wikimedia splits the response. The thumbnails themselves come directly from Wikimedia’s media host.
  • Deep category mode is also one server-side search request. Commons may warn or return incomplete results for very broad category roots; the warning is shown instead of silently pretending that the category is empty. A warning plus zero images means the category query timed out or was incomplete, not that the media thumbnails failed.
  • Several values can still require multiple requests: category Union, multiple template/statement branches, and +-separated text searches are fetched separately and merged in the browser.
  • CommonsLens coordinates application-managed Wikimedia API requests, spaces their starts, coalesces identical in-flight requests, and retries temporary failures. A short wait is therefore expected when several features are active or Wikimedia is busy.

What is saved locally

Browse does not create bookmarks, folders, a saved directory history, or a CommonsLens account record. The selected value becomes part of the current Search URL and in-memory search state. Save a file explicitly if you want a durable browser-local reference.

Important limitations

  • A category is a contributor-maintained filing decision, not a guarantee that every page inside it depicts the same subject.
  • A template is page metadata, not automatically a license, source verification, or creator identity.
  • A Q-code resolves ambiguity in the entity, but a file can still lack a Depicts statement or use a different subject statement.
  • Directory results are paginated. Scrolling loads more entries when Wikimedia provides a continuation cursor; a visible count is not a complete search-result total.
  • Directory names and counts can change as Commons and Wikidata are edited.
  • If no entries appear, check the spelling and prefix, try a broader term, or use ordinary Search to discover the vocabulary from file results. A value such as Institution:Metropolitan Museum of Art may be template content rather than an actual template page. If a deep search warns about breadth, try a narrower parent category or direct mode.

6. Search by map

Use Map when location is part of the question, not just a detail you want to read after finding a file. Map is a visual view of the current Search session and a way to start a nearby-media search by choosing a point.

Purpose

Map connects geographic context to the same search, filter, result, and viewer workflow used by Grid. It helps you discover geotagged Commons media near a place, see where the currently loaded results are located, and open a mapped file without losing its search context.

Before you begin

  • Run a search first if you want to plot a result set. You can also open Map from the Location group in Advanced filters.
  • Decide whether you want to browse existing mapped results or start a new nearby search by tapping a point.
  • Remember that Map uses coordinates you choose or public coordinates attached to Wikimedia media. It does not request your device’s live location.

Step-by-step: browse an existing search on the map

  1. Run or reopen a search. Search results must exist before Map can plot a useful result set.
  2. Choose Map. Use the Map button in the Search header. The same query, filters, sort order, and loaded session remain active.
  3. Let the camera fit the results. When there is no active location circle, Map fits the camera around loaded results with coordinates. Results without coordinates remain available in the result preview but cannot receive a marker.
  4. Read the markers. A thumbnail marker represents one result. A numbered marker represents a cluster at the current zoom.
  5. Open a result. Select a single marker to open the asset viewer. Select a cluster to open its file grid, then choose a file from that grid.

  1. Open Map. You can open it from Search or from the Location group in Advanced filters.
  2. Tap the map. The tapped point becomes the center of a nearby-media search. This updates the Search results rather than merely placing a visual pin.
  3. Set the radius. Enter a distance in kilometres in the radius panel. The default is 2 km and the smallest accepted radius is 0.5 km.
  4. Apply the radius. Press Apply or submit the radius field. The circle and result set update around the same center.
  5. Keep or clear the location. Press the close control in the radius panel to remove the location filter. Other text and non-location filters remain in the search.

  • Map markers represent only loaded results with usable coordinates. A result without coordinates is not automatically a failed search result.
  • The URL records the geographic search recipe, including latitude, longitude, radius, and the Map view flag. The current camera position and rotation are not a portable saved map drawing.
  • Opening a file from Map keeps the map-aware result queue, so returning from the viewer can preserve the surrounding search context.

What happens to your data

  • The search query, active filters, selected coordinates, and radius are sent from the browser to Wikimedia search/API services to find nearby media.
  • The visible map area requests tiles from the selected provider. OpenStreetMap receives requests for the street layer; Esri receives requests for its street, imagery, or hybrid layers.
  • Map does not ask for device location permission and does not send a live GPS position. It only uses points you tap, coordinates you reopen from a URL, or coordinates already present in public media metadata.
  • When a map search is shared, the URL can reveal the chosen latitude, longitude, radius, search terms, and filters. Treat it as a public research link.
  • Map results, camera state, and the current marker layout are not saved as a private CommonsLens collection. Bookmarks and exports must be created explicitly.

Important limitations

  • The map is not a live map of all Commons media. It plots the currently loaded Search results and can only plot items with usable coordinates.
  • Public coordinates can be missing, rounded, inaccurate, or attached to a broad place rather than the exact camera position.
  • The visible search circle is a point-and-radius query. Map panning or drawing an area is not itself a filter, and the current interface does not provide a polygon or rectangle selection tool.
  • Tile providers can be slow, unavailable, rate-limited, or subject to their own usage terms. A missing map tile does not necessarily mean the media search failed.
  • Satellite imagery is context, not evidence that a Wikimedia file was created at the exact visible location.
  • A nearby result is still subject to the same source, metadata, license, and reuse checks described in Inspect a file and Reuse media responsibly.

7. Inspect a file

Treat the asset viewer as the verification step. It keeps the file connected to the search that found it while bringing the media, source, creator information, technical facts, reuse signals, and related context into one place.

Purpose

Use the viewer to answer “What exactly is this file, where did it come from, what does Commons say about it, and what should I check before using it?” Search results are discovery surfaces; the viewer is where you slow down and verify.

Before you begin

  • Open a result card, a map marker, a bookmark, a portfolio item, or a related-media thumbnail.
  • For a reuse decision, have enough time to inspect the full source page. The viewer summarizes public metadata; it does not replace the original Commons file page.
  • If the file matters to a project, compare the displayed creator, uploader, license, source, and dimensions with the information on the source page before downloading or publishing.

Step-by-step: verify a file

  1. Start with the title. Confirm the file name and read the description or object name. A search snippet is context, not necessarily the complete description.
  2. Separate creator from uploader. The creator/author field describes the person or institution associated with the work; the uploader is the Wikimedia account that uploaded the file. They may be different.
  3. Read the dates carefully. Created/original dates describe the work or capture when metadata exists; uploaded describes when the file reached Commons. Page edit dates are a separate search concept.
  4. Check the file details. Confirm type, extension, dimensions, categories, assessments, and GPS coordinates when those facts matter to your task.
  5. Expand Structured Data. Review Commons structured statements such as creator, institution, depicts, location, or license claims. No statement is also meaningful: it means that panel has no structured claims to display.

  7. Check context when useful. Expand Related Media for another discovery path, Nearby Media for a coordinate-based search, or Global Usage to see Wikimedia pages that currently embed the file.
  8. Choose your next action. Bookmark the file for later, download an appropriate size, open the source page, visit the uploader’s portfolio, or return to the result set.

Navigate the result queue

  • On desktop, use the left and right navigation buttons or the keyboard Left and Right arrow keys.
  • On a touch device, swipe through the result pages when the file came from a queue.
  • The header shows the current position, such as 3 OF 50. A direct file link instead shows DIRECT LINK and has no surrounding result queue.
  • When you approach the end of a paginated search or portfolio, CommonsLens can load another page so the viewer can continue beyond the first batch.

Creator and uploader

Dates

Categories and assessments

These are public Commons labels and assessments. They help discovery but can be incomplete, outdated, or maintained differently from file to file.

GPS coordinates

Coordinates are public metadata when present. They may be precise, approximate, or absent; use them as context rather than ground truth.

Use the optional context sections

  • Structured Data (Wikidata): expands on demand and displays statements stored for the file on Commons, such as depicts, creator, institution, and license.
  • Related Media: expands on demand and asks Wikimedia for files considered similar to the current file. Selecting one opens a new viewer queue.
  • Search All Media Near This File: appears when usable coordinates are present and opens a 2 km Map search centered on the file.
  • Global Usage: expands on demand and lists Wikimedia project pages that currently use or embed the file. It is a usage signal, not a complete list of every copy on the internet.
  • Portfolio: appears beside the uploader and opens that username’s upload view.

What happens to your data

  • Opening a result requests the media preview and public metadata needed for the viewer from Wikimedia services or Wikimedia-hosted media.
  • Expanding Structured Data, Related Media, or Global Usage triggers the corresponding additional public request. Those panels are not fetched just because the viewer opened.
  • Changing WEB/FULL changes which image URL the browser displays. The preference is stored in this browser’s local storage when possible; the viewer does not upload the file or create a private copy.
  • Opening the source, full license, related page, portfolio, or usage page navigates your browser to that external/public page. Those providers receive their ordinary web request.
  • Opening a result from Search creates a temporary queue context so next/previous navigation and returning to the source search work. A same-tab session-storage snapshot may preserve the loaded queue across a reload; it is not an account, cloud library, or media backup.
  • Bookmarking, downloading, copying attribution, or exporting are separate actions. Only the action you request changes local storage, the browser clipboard, or your download location.

What is saved in the URL

A viewer URL can contain the file title and the context that opened it, such as Search filters, Map state, author name, bookmark query, pipeline source, or related-file context. It does not contain the media bytes. Anyone who receives the link may be able to see the search terms, filters, coordinates, or username encoded in it.

Important limitations

  • Metadata fields can be empty, stale, inconsistent, or written by different contributors. Missing metadata is not proof that a fact is false.
  • A generated attribution or reuse summary is a convenience based on available metadata. The original Commons source page and full license remain authoritative.
  • Related Media is a discovery aid, not a guarantee of visual, historical, or subject equivalence.
  • Global Usage only reflects the Wikimedia usage data returned by the provider. It does not prove that the file is unused elsewhere or that every listed use is legally correct.
  • Large originals can be slow or expensive to load. Keep WEB selected for inspection and use FULL or Download Original when the task actually requires the larger file.
  • A direct file link can open without the original search queue. Reopen the source search when you need the surrounding result context.

8. Check reuse and create attribution

CommonsLens turns available Wikimedia rights metadata into a readable reuse checklist and copy-ready attribution formats. It helps you prepare a responsible starting point; it does not grant permission or replace the original license.

Purpose

11. Download files and export metadata

CommonsLens separates retrieving media from exporting a research manifest. The persistent download queue lets you collect files while you browse, then either create one or more locally verified ZIP parts or export a metadata-only CSV.

Important safety boundary: CommonsLens verifies transport, metadata consistency, file structure, and available Wikimedia integrity values before it creates a download. It is not an antivirus scanner, malware-removal service, sandbox, rights clearance service, or guarantee that a file is harmless to open. Your safety remains your responsibility.

Understand the download queue

The queue is a browser-local, metadata-only collection of public Wikimedia file references. It is mounted once at the application shell, so it remains available while you move between Search, Map, Bookmarks, folders, author portfolios, viewers, and other media views. It also survives a page reload when the browser retains site storage. No media bytes are fetched merely because a file was selected.

  • Long-press a media card to enter selection mode, then tap cards to add or remove them.
  • The queue is keyed by the canonical media URL. Selecting the same file from another page does not create a duplicate; the source context is retained as metadata.
  • The queue is bounded at 500 entries. This limits browser-local state and prevents an accidental selection from becoming an unbounded job.
  • Clear removes an idle queue. Minimize only collapses the tray into a floating button; it does not remove the selection or stop a job.
  • Cancel stops an active ZIP job, prevents the current incomplete part from being emitted, and clears the queue. ZIP parts already handed to the browser cannot be recalled.

Choose the right output

Download an individual file

Use the viewer’s Download Original action or a card’s download control. Images and vectors may offer smaller derivatives. Individual downloads are validated before the browser is asked to save them.

Download a selection

Build the persistent queue across any supported media view, then choose Download ZIP. The browser receives numbered ZIP parts containing only media that passed the archive verification path.

Export a collection manifest

Choose Export CSV when you want metadata and Wikimedia URLs without fetching media bytes. The CSV is a research manifest, not a media archive.

Export a pipeline definition

Use the pipeline’s JSON export when you want to move or back up the graph itself. This describes nodes and settings; it does not package the media returned by the pipeline.

Open the source page

Use the source-page action when you need the canonical Wikimedia description, complete licence text, revision context, or a file type CommonsLens does not download directly.

Download an individual file

  1. Open the file or use the card action. In the viewer, choose Download Original. In a result grid, use the download control on the card when it appears.
  2. Choose a size when offered. Image and vector files can offer Small, Medium, and Large derivatives as well as the original. A derivative is smaller and faster to transfer; it is not the same file as the full-resolution original.
  3. Wait for validation. CommonsLens fetches the selected media response, screens it, and only then creates the browser download. If a check fails, the file is not saved and the interface shows a blocked-download message.
  4. Check the browser download. The browser saves the verified bytes according to your browser’s download settings. CommonsLens does not choose your download folder or maintain a private copy of the file.
  5. Check the source before reuse. Download security does not establish copyright permission. Open the source page and verify the licence, attribution, creator, source, and any restrictions before publishing or redistributing the file.

Download a selected collection as verified ZIP parts

  1. Build the queue. Select files from Search, Map, Bookmarks, folders, author portfolios, or another media view. The queue stores metadata and URLs only; the original bytes are fetched later.
  2. Start Download ZIP. CommonsLens takes a queue snapshot and revalidates each selected file against fresh Wikimedia metadata immediately before fetching its bytes. A stale or changed queue record is not trusted by itself.
  3. Wait for each file’s checks. The archive path requires a trusted HTTPS Wikimedia media URL, a successful bounded response, matching extension/MIME/signature information, matching byte length when available, and a matching Wikimedia SHA-1 when available. Only the verified byte buffer enters a ZIP.
  4. Expect numbered parts for large selections. Each part contains at most 100 media entries and uses a 256 MiB archive target with a smaller media-payload budget reserved for ZIP metadata. Parts are named like commonslens_media.part-001.zip. The old part is handed to the browser before the next batch is assembled.
  5. Read every part’s manifest. Each ZIP contains commonslens_verification_manifest.csv and README.txt. The manifest records status, ZIP entry, source page, verified URL, MIME/type observations, checks performed, expected and observed sizes, SHA-1 values, licence/attribution fields, and failure reasons for skipped files.
  6. Review complex files carefully. Recognised SVG, PDF, DjVu, XCF, STL, and other complex formats may be included as opaque bytes for the archive workflow. CommonsLens does not unpack, execute, render, malware-scan, or promise that these files are harmless to open.
  7. Watch the browser downloads panel. One action can produce multiple ZIP downloads. Chrome or another browser may ask permission for multiple downloads, and the browser—not CommonsLens—controls the destination and final file lifecycle.

Why ZIP parts exist

A browser-based ZIP builder must temporarily retain verified media while it calculates checksums, writes ZIP headers, and creates the browser Blob. A count-only limit would be unsafe because 100 small images and 100 large videos have very different memory costs. CommonsLens therefore rotates a part when it reaches either 100 media entries or its byte budget. The completed batch is handed to the browser, its object URL is released, and the next batch is started after the event loop yields.

This reduces peak application memory and keeps verification cooperative so the interface can continue repainting, but it cannot force the browser or operating system to release a download immediately. Keep an eye on available disk space and the browser’s download state when exporting many large parts.

Export a CSV manifest

CSV export is intentionally metadata-only. The queue CSV contains detailed public metadata and original Wikimedia URLs; it does not fetch the selected media and it does not upload the queue to CommonsLens. Pipeline Dataset Manifest exports remain CSV-only and never download media bytes.

CSV fields are quoted and values beginning like spreadsheet formulas are neutralised, but a CSV is still untrusted data. Review it before opening it in a spreadsheet or passing it to another pipeline. A CSV link can lead to a file that has changed since the row was created, so re-check the source page before downloading from it elsewhere.

The browser, its caches, its download history, and the final files remain under your browser and device controls. For CSV or pipeline JSON, the browser constructs the file locally from app state.

Rights and provenance remain your responsibility

12. Build a visual pipeline

A pipeline is CommonsLens’s visual workspace for turning one or more Wikimedia Commons queries into a repeatable collection, transformation, preview, or metadata export. This is the deepest section in the guide because the canvas is not just another search form: the order and shape of the graph determine what Wikimedia is asked for, what is combined in your browser, and what finally becomes an output.

GETTING STARTED WITH COMMONSLENS PIPELINES

Start with one source node, connect it to the condition or transformation you need, and finish with a preview or Dataset Manifest output. Read the graph from left to right: sources create media sets, filters narrow them, set operations combine branches, transforms shape them, and sinks finish the workflow.

The fastest first experiment is Text Query → Format Filter → Dataset Manifest. Add the source from the palette, select each node to edit its settings in the inspector, connect the nodes in order, and run a preview before exporting. The rest of this section explains what each node means and how to diagnose a graph that does not produce the expected files.

What a pipeline is

A pipeline is a directed graph. Each node receives a working collection of media records, changes it or starts a new branch, and passes the result through a visible connection. In this guide, a media set means the current list of Wikimedia files plus the metadata CommonsLens has loaded for those files.

The application defines 31 registered node types: 27 are available to add from the current palette, while four legacy sink types remain readable only so older saved graphs do not break. The complete reference below includes all 31.

Sources start branches

A source has no input. It creates a media set from a text query, category, subject, statement, template, location, uploader, or related file.

Filters narrow branches

A filter has one input and one output. It adds a condition such as licence, format, dimensions, date, language, or excluded terms.

Set operations join branches

A set node has two inputs, A and B. It combines two branches as a server-side constraint or as a URL-based union, intersection, or difference.

Transforms shape results

A transform has one input and one output. It deduplicates, sorts, samples, selects export fields, or fetches optional enrichment.

Sinks finish a branch

A sink is terminal. The current supported output is Dataset Manifest (CSV). Preview is exposed through that workflow, while older sink types remain readable for migration.

The execution model: compile first, fetch later

On a simple source → filter → filter chain, CommonsLens does not fetch every intermediate list. It compiles the source and query-capable filters into one Wikimedia search request, then materializes the branch when a preview, transform, set operation, or sink needs actual records. This usually means fewer requests and more accurate server-side filtering.

Once a branch has materialized, later work happens against the records already loaded in the browser. That distinction matters. Format, resolution, date, and excluded-term filters can still be evaluated locally from available fields. Licence, quality, language, and colour-depth conditions depend on structured query information that may not be present on each loaded record; if placed after a materialized branch such as Author Uploads or Geosearch Browse, CommonsLens warns and passes those items through rather than pretending the filter succeeded.

Original-date previews are intentionally bounded: “Originally made / photographed” is read from per-file metadata such as DateTimeOriginal, not from the indexed creation or edit dates. A pipeline preview checks one provider result page and may therefore show fewer than 100 records—or none—even when later pages contain matches. Use Run full export when the date-filtered dataset needs to continue through additional pages.

What a pipeline requests and downloads

There are two different kinds of work in a pipeline: requesting information about files, and downloading the files themselves.

1. Source requests

Sources ask Wikimedia for matching file records and metadata. The response includes file information and media URLs; the pipeline does not download every original image.

2. Optional metadata

Rights/attribution, technical image information, Structured Data, and global usage are additional metadata requests. They add information to rows, not media files to your computer.

3. Preview display

The preview may load thumbnails so the grid can show images. This is display activity, not a full media download or an image archive.

4. CSV export

The browser builds the CSV from the records and metadata it has, then downloads that small CSV file locally. The URLs inside it still point back to Wikimedia.

Only an individual download retrieves media bytes. Use the viewer’s download action when you actually want an image, audio, video, or document file on your device.

The most important set-operation distinction: use Combine Constraints (AND) when both branches are still query-capable and should become one server-side query. Use Intersect when you already have two materialized lists—such as an author portfolio and a geosearch result—and want the files whose URLs occur in both lists.

Build a pipeline step by step

  1. Start with a clear outcome. Decide whether you want a browsable preview, a result set sent to Search, or a CSV manifest. A pipeline must contain a Dataset Manifest (CSV) node before it can run.
  2. Add one or more sources. Search the node palette, add a source to the canvas, and configure it in the inspector. A branch can have one source; add another source when you need two branches to combine.
  3. Configure the node before judging its output. Set the query, Q-codes, usernames, coordinates, filters, limits, or export options in the inspector. The short text inside the node is a summary of its current configuration.
  4. Connect outputs to inputs. Drag from a node’s output to the next node’s input. Ordinary nodes accept one incoming connection; set operations require both an A and a B connection. A source cannot receive input, and a cycle is rejected.
  5. Preview early. Use the Dataset Manifest preview action to inspect up to 100 records in the image grid and raw table. Preview mode is deliberately capped and is for checking logic, not for proving that a large export is complete.
  6. Read node statuses. The canvas reports running, successful, warning, and error states. Warnings often mean a filter was placed after a materialized branch, rights metadata is disabled, an optional metadata request failed, or a result is intentionally partial.
  7. Run the final export. Use Run full export on the Dataset Manifest node. This follows continuation pages to build the manifest and downloads a metadata-only CSV; it does not download the media files.
  8. Save or move the graph. Edits autosave to this browser. Rename the graph for the saved-pipelines list, export it as JSON for a portable definition, or import a JSON definition into another browser profile.

  • Edits to the current graph autosave in this browser’s IndexedDB. There is no separate Save button for each edit.

What happens to your data during a pipeline run

CommonsLens is a browser client. Query-capable sources and filters are sent to Wikimedia as search/API requests. Author Uploads, Geosearch Browse, and Enrich use their respective Wikimedia endpoints. Results and optional enrichment are held in the browser while the graph runs, and query/enrichment cache entries may be stored locally in IndexedDB. The app does not send your graph to a CommonsLens application server.

A pipeline can contain sensitive research context even when it contains no account information: query terms, usernames, coordinates, file titles, category names, and node notes can all be present in the saved graph or exported JSON. Do not put secrets or private information into a pipeline. Provider requests still expose ordinary web-request information to Wikimedia and other services involved in the request.

Common pipeline mistakes

Using AND when you need an overlap

Combine Constraints (AND) only works before both branches are fetched. For an uploader list plus a browse-mode geosearch, use Intersect.

Putting a semantic filter too late

License, Quality, Language, and Color Depth may pass through after a materialized branch with a warning. Put them directly after a query-capable source whenever possible.

Assuming preview is complete

Preview is deliberately capped. A successful preview proves that the graph can produce records; it does not prove that every match has been fetched.

Expecting Field Select to change the images

Field Select changes export records, not the media bytes or the visual identity of the result items.

Enriching a large result

Enrichment can create many additional requests because it can run for every incoming item. Enable only the bundles you need, and put Sample / Limit before Enrich when you intentionally want a smaller test run.

Confusing graph export with result export

Pipeline JSON preserves the recipe. Dataset Manifest CSV preserves metadata and URLs. Neither is a downloaded media archive.

CommonsLens has no account or cloud workspace. Sharing happens through URLs and exported files; bookmarks, folders, saved pipelines, caches, and viewer preferences stay in the browser that created them unless you deliberately export something.

How to share a search

  1. Set up the search. Enter the query, apply filters, choose the media tab, and switch to the map view if that is part of what you want to show.
  2. Copy the address bar URL. CommonsLens keeps the current search state in the URL as you change the query and filters. You can copy it from the browser; there is no account-based share record to create.
  3. Send the URL. The recipient opens it at the CommonsLens origin. The app decodes the parameters, restores the search controls, and requests current results from Wikimedia.
  4. Explain time-sensitive context. If the recipient needs the exact files you saw, send a CSV manifest as well. A URL shares the recipe for the search, not the state of Wikimedia at the moment you copied it.

What a search URL can contain

Search links can carry far more than a simple text query. Depending on the search, the address may include categories, excluded terms, Wikidata subjects or statements, licence presets, quality settings, dimensions, file sizes, dates, language, location coordinates, a nearby-title search, templates, sort order, and the map/grid view. Collection values are encoded into query parameters so the app can reconstruct them after a reload.

URLs are not private notes. Query strings can appear in browser history, copied messages, screenshots, referrer data, or server/provider request logs. Do not put passwords, private names, confidential project identifiers, unpublished research terms, or sensitive locations into a search, pipeline name, note, or shared URL.

How to share a file or viewer context

When you open a file, the address bar contains a /view URL with the file identifier and, where relevant, the source context. Copy that URL to point someone to the file. If the link came from Search, an author portfolio, Bookmarks, a related list, a map, or a pipeline result, CommonsLens uses that context to rebuild navigation when it is available.

The link is resilient but not a snapshot. A queue identifier may refer to a temporary session copy of loaded records. If the recipient does not have that session, CommonsLens can refetch a supported source or load the single file directly, but the exact list, pagination position, or metadata may differ.

Move work between browsers

  1. For a search recipe, copy the URL. This is the lightest portable form and makes the recipient run a fresh search.
  2. For a pipeline recipe, export JSON. Use the pipeline menu’s Export as JSON, then transfer the downloaded file and import it on the other device.
  3. For a result dataset, export CSV. CSV preserves the selected metadata and URLs, not the media bytes or local organization.
  4. For bookmarks, export a manifest and recreate organization manually. The bookmarks CSV is a portable record of selected media, but it does not restore the local bookmark store or folder membership automatically.

Privacy and provider boundaries

Local state is not sent to a CommonsLens account because CommonsLens does not have one. When you open a shared URL, however, your browser makes the corresponding requests to Wikimedia and any map provider involved. Those providers receive ordinary web-request information and the query or resource needed to answer it under their own policies.

Sharing a URL can therefore reveal both the URL contents and the fact that the recipient opened it. Sharing a CSV or pipeline JSON can reveal more: CSV includes metadata and links, while JSON can include your node configuration, search terms, usernames, coordinates, titles, and notes. Inspect those files before sending them.

Sharing checklist

  • Use a search URL when you want someone to reproduce a query, not when you need to guarantee an identical result set.
  • Send a CSV alongside the URL when the observed file list or metadata matters.
  • Export pipeline JSON only after removing private terms, coordinates, usernames, or notes that the recipient does not need.
  • Remember that a bookmarks URL does not share the bookmark collection itself.
  • Do not treat browser-local persistence as backup. Export important pipelines and manifests to a location you control.

14 / Privacy, rights, and responsible use

14. Rights, privacy, and responsible use

CommonsLens helps you discover, inspect, and organize public Wikimedia media. It does not own the media, grant a new licence, certify a proposed reuse, or replace the terms of Wikimedia, map providers, or the original source pages.

The three separate questions before reuse

QuestionWhere to checkWhy it matters
What does the copyright licence allow?The original Wikimedia Commons file page and its complete licence notice.Permissions may require credit, a source link, licence notice, modification disclosure, or share-alike treatment. A download button is not permission by itself.
Who should receive credit?The creator/artist/author fields and the source page—not only the uploader username.The account that uploaded a file may be an institution, bot, shared account, or transfer account. Uploader and creator are not interchangeable.
Are there rights beyond copyright?File descriptions, depicted people and places, source/institution notes, local law, and context of your intended use.Privacy, publicity/personality rights, moral rights, trademarks, patents, contractual restrictions, cultural concerns, and sensitive subjects can matter even when the copyright licence is free.

Rights-check workflow

  1. Open the source page. From the viewer, use View Source Page. Treat the original Wikimedia description and licence as authoritative if CommonsLens and the source differ.
  2. Identify the creator. Read the creator, author, source, institution, and uploader fields separately. Do not credit an uploader automatically when the file identifies another creator.
  3. Read the full licence and conditions. Record the licence name and link, required credit line, source link, modification notice, share-alike requirement, and any author-requested wording.
  4. Match the licence to your actual use. Commercial, advertising, political, medical, defamatory, merchandise, and sensitive-person contexts can raise additional issues beyond a basic copyright licence.
  5. Check people, places, and marks. Consider identifiable living people, private locations, cultural materials, trademarks, logos, and any restrictions described by the source or rightsholder.
  6. Preserve your evidence. Keep the source URL, file title, creator, licence, access date, and the attribution you used. A CSV manifest can help organize this record, but it is not a substitute for the source page.

What CommonsLens does—and does not—decide

CommonsLens can help you

Find licence-filtered candidates, inspect creator/uploader/source fields, open the original page, generate an attribution draft, and export metadata for your own review.

CommonsLens cannot certify

That a file is copyright-clear for your exact use, that every metadata field is complete, that a person consented, that a cultural restriction is absent, or that a generated attribution is legally sufficient.

Missing information means verify

A blank licence, creator, date, or source field is not permission. Treat uncertainty as a reason to inspect the source page or seek permission/advice.

Generated attribution is a draft

Copy-ready attribution is a convenience assembled from available metadata. Compare it with the licence and source page, then edit it to satisfy the actual requirement.

Privacy: what CommonsLens itself does not collect

CommonsLens does not require an account and does not maintain a private application database of your research. It does not intentionally load analytics, advertising pixels, behavioural tracking, fingerprinting, session replay, or interaction telemetry. Bookmarks, pipeline graphs, notes, query caches, and viewer preferences are stored in your browser as described in Section 13.

This is data minimisation, not invisibility. Your browser still contacts GitHub Pages for the site, Wikimedia services for search and media, and OpenStreetMap or Esri when you use those map layers. Those providers receive ordinary web-request information and apply their own terms and privacy policies.

Privacy when using URLs and exports

  • Search URLs can expose query terms, category names, usernames, file titles, dates, and coordinates in browser history, copied messages, screenshots, or referrer contexts.
  • Pipeline JSON can contain search settings, usernames, coordinates, node titles, and notes. Review it before sending it to someone else.
  • CSV manifests can contain creator, uploader, licence, location, usage, and source metadata plus Wikimedia URLs.
  • Do not place passwords, private research terms, personal data, or confidential project identifiers into a query, URL, pipeline, folder name, or note.
  • Clear site data when you need to remove browser-local bookmarks, pipelines, caches, and preferences; remember that files already downloaded are controlled by your operating system.

Use public media with context and care

Publicly reachable does not mean context-free or harmless to redistribute. Consider whether a file identifies a living person, reveals a sensitive location, documents a vulnerable community, depicts trauma, or could be used to harass, mislead, or expose someone. Do not use CommonsLens to target people, compile invasive dossiers, bypass access controls, or republish sensitive material without considering the consequences.

Geographic coordinates deserve particular care. A map result may reflect public metadata, but publishing an exact location can create a different risk from viewing it in context. Use a less precise location or omit it when your audience and purpose do not require precision.

Be considerate of Wikimedia and map services

  1. Use the interactive app as a human tool. Do not turn the website into a scraper, crawler, bot, or high-volume automation endpoint.
  2. Space out expensive work. Pause between large searches, enrichment runs, map exploration, and full pipeline exports. Avoid many query-heavy tabs or rapid refresh loops.
  3. Respect provider signals. Do not bypass rate limits, retries, backoff, technical safeguards, robots rules, or provider usage policies.
  4. Use official APIs for sustained automation. If your research needs repeatable high-volume collection, use the relevant official API directly and follow its identification, throttling, licensing, and attribution guidance.
  5. Do not bulk-prefetch maps. Request only the visible map area you need; do not prefetch or archive large tile areas for offline use through the interactive site.

15 / Troubleshooting

15. Troubleshooting

Troubleshooting is easiest when you first identify which layer failed. A problem may be in CommonsLens itself, in the Wikimedia API, on Wikimedia’s media host, in a map provider, in your browser’s local storage, or in the search or pipeline configuration. The visible symptom is not always the cause: a broken thumbnail does not necessarily mean that a file is gone, and an empty result does not necessarily mean that Commons has no matching files.

Start here: do not clear all browser data as your first response. That can delete local bookmarks, saved pipelines, cached work, and viewer preferences before you have preserved them. Export a pipeline or CSV first when possible, then simplify the task and retry.

Use the Wikimedia request log

When you need to see whether a request was made and what Wikimedia returned, open the request log from the small receipt icon. On the landing page it is in the top-right corner; in the Search filter workspace it is at the bottom of the primary sidebar, including the collapsed sidebar rail.

The log groups app-managed Wikimedia requests by operation:

GroupExamples
AutocompleteSubject, property, category, and template suggestions.
SearchNormal Search and filter-result requests.
PipelinePipeline source, pagination, and enrichment requests.
BrowseCategory, template, and depicted-subject directory requests.
MetadataFile information and optional metadata requests.
Thumbnail / MediaPreview-sized and other Wikimedia-hosted media requests.
DownloadRequests made for an explicit media download.
  • Each entry contains only the request URL and returned status. The category is supplied by the group heading.
  • A NO_RESPONSE entry means the app attempted the request but did not receive an HTTP response.
  • Retries are recorded as separate attempts, so repeated URLs can show how Wikimedia responded across retries.
  • The log updates while it is open. Use Clear to remove the current entries.
  • The log is kept in the current page session and is not a saved history or CommonsLens account record. URLs can contain search terms, category names, Q-codes, usernames, or coordinates, so treat the visible log as potentially sensitive.

The first 60 seconds

  1. Read the exact message. Note whether CommonsLens says that there are no matches, a request failed, a provider is unavailable, a download was blocked, or local data could not be read. These are different problems with different remedies.
  2. Check the URL and network. Confirm that the address is the expected CommonsLens route, that the page is not offline, and that your browser has not blocked requests, downloads, pop-ups, cookies, or site storage.
  3. Retry once after a pause. Wikimedia requests are deliberately serialized and throttled. A 429, 503, timeout, or “busy” message may be temporary. Wait rather than repeatedly refreshing the same expensive request.
  4. Simplify the work. Remove one filter, reduce a map radius, shorten a date range, reduce a pipeline preview, or temporarily disable enrichment. If the simpler version works, add complexity back one change at a time.
  5. Try the source page. If a file or preview fails, open View Source Page. If the source page also fails, the issue is probably with Wikimedia, the network, or the file itself rather than the CommonsLens presentation.
  6. Preserve evidence before resetting anything. Copy the URL, export a pipeline or CSV if available, and record the exact message. Only then consider clearing site data or opening a private window for a controlled test.

Search and result problems

The result count is the outcome of all active constraints together. CommonsLens can combine text, media type, file format, categories, depicted subjects, structured-data statements, dates, dimensions, file size, licence, quality, location, title/full-text mode, and other filters. When the result set is empty, assume that at least one constraint is doing exactly what it was asked to do before assuming that the service is broken.

  1. Start with the visible chips. Remove the most restrictive or least certain chip first: a narrow format, exact date range, small radius, title-only mode, required licence, or quality condition.
  2. Check the logic. Multiple values may mean “all of these” or “any of these,” depending on the control. If you need files matching either of two subjects or formats, verify that you did not accidentally request both.
  3. Check the collection. Select the appropriate Images, Audio, Video, Documents, 3D, or other media view. A file can be present in Commons and still be excluded by the selected media type or format.
  4. Broaden the query deliberately. Try a shorter phrase, a related spelling, a category, or a broader date/location range. Then add the original constraints back to find which one removes the result.
  5. Reopen the source. Search results and metadata are live service data. If a result is important, save its source URL and verify the file page before relying on its presence, absence, or rights information.

Media, viewer, and map failures

CommonsLens reads metadata from Wikimedia services and media bytes from Wikimedia’s media storage. Maps add another external dependency. These services can fail independently, so use the following distinction:

Data works, presentation fails

The result card, title, or source link is present but the thumbnail, viewer, or map tiles are absent. Try another preview, switch map layers, disable a blocking extension, or open the source page.

Presentation works, data is absent

The page loads normally but no files or map points match. Review query, filters, coordinates, radius, and media type. A healthy interface does not make a narrow query broader.

The source also fails

If Wikimedia’s original file page or media URL cannot load, wait and retry later, check your connection, and avoid repeated refreshes. CommonsLens cannot repair a deleted file or an unavailable upstream service.

Downloads and security refusals

A download refusal is intentionally different from a network error. CommonsLens screens direct media downloads so that a URL does not silently turn into an unexpected local file. It checks that the URL is HTTPS and on Wikimedia Commons media storage, applies an extension and size policy, compares the response with expected length and type where possible, checks file signatures and SHA-1 integrity when available, rejects executable/archive content, and creates a safe output filename.

This is a protective gate, not an antivirus or a legal review. A file can be legally reusable and still be unsafe for a particular device or workflow. Conversely, a blocked format can be perfectly legitimate but unsuitable for the direct browser-download path. When a refusal is appropriate for your work, use the source page or the documented export URL, then apply your own operating-system and organisational scanning procedures.

Local state, saved work, and shared URLs

CommonsLens is intentionally usable without an account. That means bookmarks, folders, saved pipelines, caches, viewer preferences, and temporary queues live in browser storage rather than in a cloud account. “It disappeared” is therefore usually a browser-profile or storage question, not a server-side account question.

  • Same site origin: http and https, different hostnames, different ports, and different deployments have separate storage.
  • Same browser profile: another browser, profile, device, or private window will not automatically have the same local data.
  • Storage permission: private browsing, disabled site data, browser privacy settings, extensions, and storage eviction can prevent persistence.
  • Different kinds of state: bookmarks and saved graphs are longer-lived local state; viewer queues are session state; search results are normally re-created by running the URL again.
  • Back up before maintenance: export bookmark metadata or pipeline JSON before clearing site data, changing profiles, or uninstalling a browser.

Shared URLs are useful instructions for repeating a search, not immutable evidence. They can contain query terms, usernames, categories, dates, and coordinates, and those values can be visible in browser history or messages. Remove sensitive information before sharing and verify current results again when the work matters.

What not to do

  • Do not hammer refresh on a rate-limited or busy request.
  • Do not conclude that “no results” means that Commons has no relevant files until you have checked filters, media type, spelling, dates, and location.
  • Do not treat missing creator, licence, or source metadata as permission to reuse a file.
  • Do not clear site data before exporting important bookmarks or pipeline definitions.
  • Do not treat a partial pipeline run or partially enriched CSV as complete.
  • Do not bypass a download safety refusal by changing file extensions or trusting an unfamiliar file automatically.
  • Do not use the interactive site as a high-volume scraper or as a way to defeat provider limits.

Reporting a problem well

If the same failure remains after the steps above, a useful report lets someone reproduce the smallest failing case. Include:

  1. The route and action. For example: Search, Map, Viewer, Bookmarks, or Pipeline; then say which button or control you used.
  2. The exact message. Copy the visible error or warning instead of paraphrasing it. Include whether the page was loading, retrying, or already showing results.
  3. A minimal reproduction. Share a small query, a redacted URL, or a reduced pipeline. Remove private names, confidential terms, and sensitive coordinates.
  4. Your environment. Record browser and version, operating system, whether private browsing or an extension was involved, and whether the source page worked.
  5. Timing and scope. Record the date/time, whether the issue affects one file or every query, and whether retrying later changes the result. This helps separate a transient provider problem from a repeatable app problem.

For rights, metadata, or availability questions, include the original Wikimedia source page when appropriate. For security refusals, include the refusal category and source page rather than uploading or sharing the downloaded file.
